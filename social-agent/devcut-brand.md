# DevCut Social Brand Rules

## Audience

Primary audience: software developers, especially students, early-career engineers, indie hackers, and working developers who use VS Code and understand everyday build/test/install pain.

## Brand personality

DevCut should feel:

- Developer-native
- Funny before promotional
- Slightly chaotic, self-aware and internet-literate
- Clear, not corporate
- Transparent about being an early-stage startup
- Comfortable showing mistakes and learning in public

Avoid sounding like:

- A finance/get-rich-quick account
- A generic SaaS marketing page
- An aggressive ad network
- A motivational influencer

## Content rule

A meme or Reel should still be enjoyable even if the viewer has never heard of DevCut.

The preferred structure is:

```text
Relatable developer situation -> punchline -> subtle DevCut connection -> optional CTA
```

Do not force DevCut into every post. Some posts should exist only to earn attention and shares.

## Core topics

- npm install / package installs
- Builds taking forever
- Tests failing at the last moment
- CI/CD waits
- Merge conflicts
- Production bugs
- "works on my machine"
- Late-night debugging
- Code review pain
- Standups and unrealistic estimates
- Junior/senior developer jokes
- AI coding/tooling culture
- Developer salary and work-life memes without making misleading income claims
- Founder/build-in-public updates

## Product positioning

Simple description:

> DevCut helps developers earn from otherwise wasted build, test and install time by showing lightweight sponsored developer messages.

Any earnings/payout claims must use real current numbers. Never invent payout amounts, advertiser results, user counts, download counts or testimonials.

## Hooks

Prefer hooks such as:

- POV: ...
- Every developer after ...
- Bro really thought ...
- The build: ... / Me: ...
- Manager: "small change" / The codebase: ...
- Developers when ...

Avoid generic hooks like "5 reasons you need DevCut" unless the post is explicitly product education.

## CTA hierarchy

Use at most one CTA per post.

Preferred CTAs:

1. Share/tag a developer friend
2. Follow for developer/startup content
3. Comment with an experience/opinion
4. Try DevCut / link in bio

Do not put "install DevCut" on every post.

## Approval checklist

Before scheduling, verify:

- Is the trend still fresh?
- Would a developer immediately understand the joke?
- Does it work without needing product context?
- Is the DevCut connection natural rather than forced?
- Are product/earnings claims factual?
- Is there only one CTA?
- Could this embarrass the brand in a week?
- Does the content avoid punching down at individuals or communities?

If any answer is uncertain, hold the post for manual review.
